JVM = Java Virtual Machine

The JVM is a software engine that runs Java programs. It acts as a layer between your Java code and the operating system.

1\. Method Area: Stores class information, like the blueprint of a `Student` class.

2\. Heap Memory: Stores actual objects, like `Student s = new Student();`.

3\. Stack Memory: Stores local variables and method calls, like `int age = 20;` inside `main()`.

4\. PC Register: Tracks which instruction the CPU-independent JVM execution should execute next, like moving from line 5 to line 6.

5\. Native Method Stack: Handles methods written in other languages like C/C++ that Java calls.

Easy trick to remember:

- Method Area → Blueprint
- Heap → Objects
- Stack → Local variables & method execution (the actual values stored like `int age = 20;`)
- PC Register → Next instruction
- Native Stack → Non-Java methods





string constant pool:That special storage area is called the String Constant Pool. that only contains string literals. 

if String a="Java", b="Java", then both a and b refer to same object saved in String Constant pool.


flow goes like this:

stack memory (stores references of objects)-> Heap Memory (stores actual objects) -> String Constant Pool (stores string literals)










String str = "Daksh";

Stack(str) -> string constant pool ("Daksh")


String str1 = new String("Daksh");

Stack(str1) -> Heap Memory (new String("Daksh")) -> string constant pool ("Daksh")
